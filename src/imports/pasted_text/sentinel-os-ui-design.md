Prompt:

Design a premium mobile application UI (Android-first) for an AI-powered security system called SentinelOS, which acts as a real-time fraud protection layer across calls, links, UPI payments, screen content, and app installations.

The design should feel like a native OS-level security feature, not a cluttered dashboard. It must be clean, calm, minimal, and highly structured, with a strong focus on trust, clarity, and intelligent assistance. Avoid dark themes, neon colors, or flashy gradients. Use a light, soft color system with subtle contrast, giving the product a refined, flagship-quality feel similar to Google or Apple system apps.

The application should follow a bottom navigation structure with five primary tabs: Home, Activity, Shield, Reports, and Settings. Do not use a sidebar, as this is a mobile-first experience.

The Home screen should act as a smart dashboard, but remain minimal and uncluttered. It should prominently display a unified threat score using a circular indicator with clear status states like safe, warning, or threat detected. Below that, show the five protection modules — Call Shield, Link Shield, UPI Shield, Screen Shield, and App Shield — each represented as clean cards with status indicators and small alert badges. Include a short live activity feed showing only the most recent few events, not a full list. Add compact, horizontally scrollable stat cards for metrics like threats blocked, active alerts, calls analyzed, and community database size. Include a small section for quick actions such as scanning a link, checking a UPI ID, or reporting a scam.

The Activity section should replace traditional tables with a clean, scrollable list of cards representing detected threats. Each item should include the type of threat, the entity involved, a score out of 100, detected signals shown as small tags or icons, and a timestamp. Tapping an item should open a detailed view that explains the reasoning behind the detection, shows evidence, a signal breakdown, and allows the user to give feedback such as marking it as a real scam or false alarm.

The Alert History should visually represent the four alert levels — info, warning, alert, and block — using clearly differentiated but soft color coding. Each alert should be presented as a card showing the score, triggered signals, explanation, and what action was taken, maintaining clarity without overwhelming the user.

The Shield section should present an overall system status, showing that all protection modules are active, along with a clear “You are protected” message. Each module should be accessible as a separate detail screen. These module screens should not feel like data dashboards but should instead use structured cards and sections to present deeper insights.

Within the Call Shield, show a simple timeline of how calls are analyzed from incoming ring to final alert, along with daily stats for safe, warned, and blocked calls, and a dedicated section highlighting detection of scam patterns like isolation or urgency language.

Within the Link Shield, show the scanning process using clean stacked cards representing different verification sources, each displaying status and latency in a simplified way. Include a section that demonstrates how suspicious URLs are scored, using clear examples rather than technical tables.

Within the UPI Shield, highlight detection of suspicious combinations such as a call occurring simultaneously with a payment request. Show flagged UPI IDs as a simple list with report counts, and visualize how patterns are evaluated using a clean, understandable scoring display.

Within the Screen Shield, display detected dark patterns in a simple list and include a small informational card about the on-device AI model, including its speed and offline capability, presented in a user-friendly way.

Within the App Shield, show alerts for suspicious app installations, including fake banking apps or remote access tools, with clear actions such as uninstall. Include a simple registry view of monitored apps, again using cards instead of dense lists.

The Reports section should visualize the scoring engine in a simplified way, showing how different signals contribute to the final threat score. Include a clean chart representing signal weights and a visual explanation of the four action tiers, ensuring it remains easy to understand for non-technical users.

The Settings section should include options to toggle each protection module, adjust alert sensitivity, manage a whitelist of trusted contacts and UPI IDs, and control privacy settings such as on-device processing and data storage. Advanced features like API health and system diagnostics should be accessible within settings but not shown prominently in the main navigation.

Throughout the app, use card-based layouts, soft shadows, rounded corners, and consistent spacing. Typography should be clean and modern, with a clear hierarchy but not overly bold. Every alert or warning must clearly explain why it was triggered and always allow the user to proceed if they choose, reinforcing a sense of control and transparency.

The overall experience should feel like a calm, intelligent guardian that works quietly in the background, surfacing only the most relevant information while allowing deeper exploration when needed.
